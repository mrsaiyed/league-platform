## T4 — Keeping leagues apart, sign-in, security

| T-490 | The job queue's owner, and what each start accepts (step 2.112, record 053, T-257, T-60). **Who owns what.** Migration 0031 makes the role `queue_owner` (no login, no powers) and the empty schema `pgboss` owned by it, open to nobody else (`public` has no right there); it grants `queue_owner` to no login. pg-boss's tables are owned by the worker's login, because PostgreSQL gives a table to the login that makes it and pg-boss does not switch role. The worker's login holds `app_user` and `queue_owner` (a plain `grant queue_owner to <worker login>`), nothing else; the website's login holds `app_user` only. The migrations' catalog does not count `pgboss` among the migrations' schemas: the migrations leave it empty and what is in it is pg-boss's. **The website** (`checkLoginRole`, which judges every login as the website's unless the caller says `worker`): every rule of T-60 and the fence as before, a table it or a role it reaches owns in any schema, `pgboss` included, refused; a membership of `queue_owner`, direct or through any other role and whatever its options, refused in plain words with `revoke queue_owner from <the role that holds it>`; any other right to use the schema `pgboss` refused with `revoke all on schema pgboss from <holders>`; `pgboss` is not a library schema for it, so a table there it may read is refused with `revoke select`. **The worker** (`checkLoginRole` with `worker`, then on a hosted database `checkQueueSchema`): every rule of T-60 and the fence as before, but a table in `pgboss` owned by the login itself or by `queue_owner` is not counted as owned; a table it or any role it reaches owns in any other schema is refused exactly as before, so a worker holding `app_user` and `queue_owner` starts, and starts again after pg-boss made its tables. In `pgboss` an ordinary table without a league column that the worker may read is let be (T-482's rule, now for the worker only); a view, materialized view or foreign table there is refused, a table with a league column must have its row-level security on and forced like any league table. `checkQueueSchema` refuses a missing schema, a schema owned by another role (`alter schema pgboss owner to queue_owner`) and a login that may not use it or make tables in it (`grant queue_owner to <login>`). **What a start does not catch (the limit).** For the worker it cannot tell pg-boss's own table from a copy table without a league column put into `pgboss` by someone holding the worker's login, `queue_owner` or the database owner's key; the worker could read such a copy, the website cannot. The columns of pg-boss's tables are not compared with pg-boss's, and triggers and rules on them are not read. A grant made while the website or worker runs is seen only at its next start. As T4 says, it catches a change or drift made by hand, not a person holding an owner's key who means harm. **One login for both (proved on the real PostgreSQL, builder 2).** The two checks together refuse one login used for both services: the website's start refuses the worker's login (it holds `queue_owner`) and the worker's start refuses the website's (it may not use `pgboss`: `grant it queue_owner`); nothing else proves the two logins differ, and nothing needs to. The website's login holds `app_user` and `sign_in_store` (record 052). Where the website is judged with a login that reads pg-boss's tables, no sentence says to drop one: a table in `pgboss` is mended by `revoke select`, beside the queue sentence that names the real fault (found on the real server: before, it said `drop table pgboss.job`). **The tables' owner keeps ADMIN of `queue_owner`.** On PostgreSQL 16 a role's maker is always given ADMIN of it, without INHERIT or SET, granted by the server itself; 0031's own grant (SET, no INHERIT) is revoked, so the owner cannot act as `queue_owner` but could grant it to itself or a login. That is the owner's key, which the guard does not defend against; it is also what lets the owner grant `queue_owner` to the worker's login when a hosted database is set up. | Agreed (delegated) | |
