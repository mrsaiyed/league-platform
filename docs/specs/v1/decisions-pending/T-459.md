## T4 — Keeping leagues apart, sign-in, security

| T-459 | Reading what an invitation link offers (`access.read_invitation`) looks the link up before it asks whether the league is there (step 2.223, review M2, completing T-449). Anyone signed in may ask; the hash of the token and the link are read first, and only a link that was found is checked against the league (its owner), its status, its program and its sender. So the invitation page at an address with no league behind it (asked with an id no league has, T-449) does the same work in the same order as a hidden league holding no such link. Before, the missing league was refused before the hash was taken, its page was ready sooner, and its answer came without the stylesheet preload (`Link` header) that a hidden league's carried. `npm run test:web` compares the two, signed in with a token-shaped invitation cookie, three times each | Agreed (delegated) | |
