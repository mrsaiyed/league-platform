## T8 — Scale, reliability and operations

| T-300 | One image, `platform.Dockerfile` (never the tracker's `Dockerfile`), runs the web app by default and the worker by a command written at its top; it copies only named paths (the root `package.json`, each workspace, `supabase/site.json`, `supabase/migrations`), runs as a user that is not root, and its own ignore file, `platform.Dockerfile.dockerignore`, lets in only those paths and never a `.env` file. Each workspace declares the outside packages its code imports (R10). GitHub builds it and starts it on every push, publishing nothing. The release command, `npm run release`, is run by a person at their own terminal, with `--hosted` and the migration login's address given for that one command only (never in `.env`, never a setting on the host) and WITHOUT its password: the command asks for the password itself at the terminal with the typing hidden, so it never lands in the shell's history or in pasted terminal text, and an address that carries a password, in that setting or as an argument, is refused in one fixed sentence that repeats none of it and says to clear it from the history (a database on this computer, without `--hosted`, keeps its present way); it passes the tracker's database guard, takes the certificate from `PLATFORM_DATABASE_CA`, opens the database through the league-making tool's own checks (`openMigrationTarget`), proves the login sees every league (a superuser or BYPASSRLS, as `require_view_of_every_league()` asks) and refuses otherwise, since a fenced login would count 0 live games, asks the person to type the Supabase project's reference (for a host that names none, the host's name) read from the connection itself, not the database's name, which is `postgres` on every project, applies the changes with `applyMigrations`, and only when every one applied names the commit to deploy by hand; a failed change names nothing (record 101). Before applying anything it counts the games live in every league and stops above 0 unless given `--go-ahead` (T-158; 0 until T-127 is proved). Going back is the previous commit deployed by hand, the database never taken back (T-156, T-183). The host is written down as a checklist, `docs/operations/render-test-copy.md`, not a `render.yaml` blueprint, so no file in the repository can create or change a service: every setting is typed by the founder and checked by eye | Agreed (delegated) | |
