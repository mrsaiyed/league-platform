## T6 — Live stats and realtime

| T-335 | "Send these plays" (S-43, step 2.148) goes through the commands door the tracker always uses, as a batch carrying `notSavedSince` and naming the session the plays were made under. Only the scorekeeper's own tap sends it, never the queue. The server decides where the plays can have been made; it never believes the device alone. It keeps each session the game was taken from (a takeover, or a lapse given away), whose it was and the game's sequence when it last answered that session while it held the game (`heard_seq`, migration 0027). It takes the batch, whoever holds the game now, only from that session's own account, only for a sequence not after `heard_seq`, and only if every event after it is that account's own: one of the batch's plays (an answer lost, or a second send), a play of an earlier batch of the same list (`sent_seq`), or an End or a reopen. Anything else (another account's play or command id, a change of players, a marking not started, a sender whose session was never taken, a sequence after `heard_seq`, too many events) refuses every play `game-moved`, and the device offers each for "Enter again" (S-77). The device names the last sequence it had from an answer while it still held the game: an answer saying the game is no longer held never moves it. A play never counts twice: the same command ids are answered `duplicate`, and every batch of a long list names the same sequence. The check and the write are one transaction under the game's lock (T-111). A session released or ended by marking not started is not kept, so its plays offer only "Enter again" (T-337)| Agreed (delegated) | |
