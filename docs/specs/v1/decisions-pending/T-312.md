## T4 — Keeping leagues apart, sign-in, security

| T-312 | A league's site notice (`site.notice`, plain text, at most 200 characters, empty for none) and "do not index" (`site.doNotIndex`, off to start) are two league settings, saved and logged like every other; core's `readSiteFacts` reads them with the league's audience and whether it has a recorded child (a league that holds a child is always "do not index", U-18), through one web port `siteFactsOf` read as no one in a page snapshot. The league's layout draws the notice once, as text in a named region above the header, and sets `<meta name="robots" content="noindex, nofollow, noarchive, noimageindex">` in the head of every page under the league; no other file under the league's pages names robots (a test), as Next.js would let a page's own replace it. Every league JSON answer, in every league and in production, carries a flat `X-Robots-Tag: noindex` (`respond`, league-api-route.ts): no answer of ours is for a search engine, and the game snapshot carries players' names at an address its page shows. Pages get no header per league: the proxy would have to read the league's settings on every answer (record 107) | Agreed (delegated) | no |
