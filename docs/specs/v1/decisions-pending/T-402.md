## T5 — Customization engine

| T-402 | S-109's yes to "children in full" is refused by `leagues.set_setting` itself (`no-child-recorded`, said in plain words) in an adult league with no recorded child, so a hand-posted yes cannot be saved where the screen offers none. The check reads who plays and the recorded children in the transaction that writes the yes. Under READ COMMITTED it sees only committed people, and a first child's put-back runs inside that child's own save before it commits, so a yes can be written only after a child is visible, and it was then given while the league had a recorded child: no lock and no migration are needed. A yes that outlives its child (binned, or a birth date corrected) is put back by the next first child. | Agreed (delegated) | |
