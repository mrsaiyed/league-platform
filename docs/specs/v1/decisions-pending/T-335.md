| T-335 | "Send these plays" (S-43, step 2.148) goes through the commands door the tracker always uses, as a batch carrying `notSavedSince`: the sequence of the server's state the device last knew when it lost the game, which its listed plays were made on. Only the scorekeeper's own tap sends it, never the queue. The server takes such a batch from whoever may score the game, whoever holds it now, only if every event after that sequence is one of the batch's own plays (their answer was lost, or this is a second send) or an End or a reopen by the same account; anything else (another device's play, a change of players, a marking not started, a sequence the game never reached, or more events than the batch and 20 more) refuses every play `game-moved`, and the device offers each for "Enter again" (S-77). A play never counts twice: the same command ids through the same door are answered `duplicate`. A long list goes in batches, each naming the sequence the one before it left. The device knows the sequence only for plays listed by a loss on that page: after a reload "Send these plays" is not offered | Agreed (delegated) | |
