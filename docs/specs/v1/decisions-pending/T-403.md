## T5 — Customization engine

| T-403 | The saves S-109 and T-402 guard take turns for one league: each one that may record a first child (a new or changed person, a person back from the bin, a time zone change), a person put in the bin, and `leagues.set_setting` when it writes the yes to "children in full" first holds the league's own row (`SELECT … FOR UPDATE`, `lock-league-row.ts`, through the store's `lockLeague`) until it commits, before it reads the people or the settings it decides on. The league row is always the first lock these saves take, so they cannot wait on each other in turn. Without it, a yes given while child A was recorded could outlive A put in the bin while child B was added, if B's save read the league before the bin committed. A league row that cannot be held stops the save. No migration. Proven by unit tests that each command asks for the lock before it reads (calls written down in order) and by the database tests on PGlite, which has one connection: the two-connection race itself is not run here. | Agreed (delegated) | |
