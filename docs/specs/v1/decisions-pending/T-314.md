## T3 — Data model

| T-314 | Coin flips are stored in `standings_coin_flips` (migration 0025): one row per flip, with the season, the level teams as an ordered list of ids (winner first), how it was made (`by-hand` or `drawn`), an optional note of 1 to 500 characters, who recorded it and when; league id, row-level security and the bin (no DELETE) as standings_adjustments. The teams are a list, not rows of their own: an insert trigger checks every id is a team of the same league and season, none twice, and the update trigger fixes the list once written. The rebuild passes the flips not in the bin to packages/sports, which already uses the latest flip covering every team of a level set (no change there); core adds the coin flip as the last tiebreaker when the season's list leaves it out and a flip exists. Recording a new order for the same teams sends the earlier flip to the bin. Only a set that is level after every tiebreaker now (worked out without flips) is accepted. "Flip for us" is drawn on the server with node's `crypto.randomInt` | Agreed (delegated) | |
