# 077 — Minutes on the game clock

Date: 2026-11-16. Step 2.189 (T-281). Serves S-71 (decided for you), S-1, T-110, T6 section 4, P7 sections 5.2 and 6. The rule was written by the area 6 lead (`docs/build/audits/minutes-and-a-set-clock.md`) and accepted by the lead; built by the builder of step 2.189.

## Problem

On the new scoring screen a scorekeeper set the clock from 16:55 to 12:00 by mistake and back to 16:55: all ten players on the court went from 3:05 played to 0:00, and the half's plays then read 16:55. The engine (`packages/sports/src/basketball/live.ts`) counted minutes in the clock's running time and, when time was put back on the clock, wound that time back and OVERWROTE the time of every later play, keeping no memory of what was there; time taken off counted for nobody. So a set and its reversal lost the period, and a set up and then down lost that time for good. The Al-Hadi tracker plays by the same engine and must not change by one second (T-16, `apps/live-stats`).

## What

- **One optional field on the engine's `Rules`: `minutesFollow?: 'game-clock'`.** Absent, the engine does exactly what it did. `setClock`, `record`, undo, redo and `clockAt` branch on it; `derive` is unchanged. `checkRules` never keeps it, so the tracker's own `rules` command (and its strict contract, which does not list it) cannot turn it on; a `rules` command sent to a game that has it keeps it.
- **Facts, kept under the field only and never rewritten:** `clock.ranMs`, the clock's true running time; `ranMs` on each play's stamp; `state.clockSets`, each set as `{ segment, ranMs, ms }`, where a segment is the stretch from one period play to the next (0 before the first), overtime included. A second set at the same moment replaces the first; a set to the time the clock would show anyway, in whole seconds, removes the entry and the clock reads exactly what it did.
- **The reckoning (`reckon`).** For each segment, L is the reading it started with (the period's length, or a set made at its first moment). Each set counts only as far as later sets of the segment do not take it back (S-71 as changed on November 17, after the reviews found a mistake that ran before it was put right kept its hold): from the last set back to the first, a set counts as the middle of three times, the period's start, what the set says the period started with (its time plus the period's running time up to it) and what the next set counts as; the last counts whole; `clockSets` keeps each set as made. The reading at running time r is the last set at or before r, as it counts, run down since; the corrected reading is that, or any later set's counted time if higher, and never above L. A moment's game time is the segment's base plus L less the corrected reading. After every set, every recorded play, and every undo or redo, each play in `plays` and in `redo` is stamped again from its facts (`clockMs` the corrected reading, `elapsedMs` the game time), and `clock.elapsedMs` is the base plus L less what the clock shows; `clockAt` keeps that while the clock runs. Plays tapped during one stoppage all sit at that one moment, so the order of taps does not matter.
- **Undo and redo of a period.** Undo drops that period's sets, and the clock time run in it counts for nobody: the period before reads, at that moment, what it read when the period was picked. Redo stamps the period play at the present moment.
- **What a set will do: `clockSetEffect(state, ms, now)`.** The engine makes the set on a copy and compares the game time: `back` (with whether it is all this period has run), `added`, `start` (the clock has not run in this period, and on the old rule still reads the period's start) or `none`; `back` and `added` carry `takesBackMs`, the part that takes back earlier sets of the period (`takenBackMs`), said as "This takes back 1:50 of an earlier change to this period's clock. Minutes and play times go back as they were." with what is left over after it. The scoring screen's clock form says it from this helper (`setEffect` in `game-clock.ts`), so it never says other than what is then done, under the game's own rule; once set, the sentence says what the engine truly did, in one line where a phone is short of room. The figures are the difference as the two clock times are shown, in whole seconds, never more than truly moved.
- **The switch.** `engineRulesOf` (`packages/core`) sets the field for every game of the new product: not a league's setting, since there is one right answer. A game brought over from the Al-Hadi tracker (`withoutMercyOrLastMinutes` in the transfer) is played with `trackerEngineRulesOf`, which leaves it out, so it keeps the tracker's numbers, in the transfer's dry run and when its taps are applied.
- **Games already recorded** keep the rules they were saved with (S-1), so they keep the old rule for life. No migration. They cannot be reckoned again from the saved state, since the old rule overwrote the times; only by replaying the game's events. Made-up data is seeded again instead. A state saved before the facts existed but still before tip-off (only line-ups) takes the new rules (`withCurrentRules`) and gains the facts: the clock's running time at zero and, if the scorer set the clock before tip-off, that set as made at the period's first moment, where the period starts (the reviews' LOW 2). An older page still open from before the release shows the old rule's minutes until it next loads the state; what is stored is the server's replay, on the game's own rules.
- **Proofs.** `tests/live-stats-game-clock-minutes.test.mjs`: the audit's eight worked examples and its three more with their "Right" column (minutes and plays' times), set forward then back, set back alone, undo and redo of a period, the helper, and properties over random taps (five on throughout totals five times the game time and each period is its start less its clock; every player between 0 and the sum of the periods' starts; set X and back is as if neither; set X then Y is set Y; a play's game time never goes down; a mistake that ran, put right to what the clock would show had it not been made, is as if never made), and the area 6 lead's four examples of a mistake that ran (minutes and plays' times). `tests/live-stats-set-clock-pin.test.mjs` pins the tracker's rule: a fixed script recorded with the engine before this step gives the very same state, and each example gives its "Today" result. `tests/browser/set-clock-minutes-test.mjs`: the worked example in a browser ends with 3:05, and the sentence after a set fits, in one line where a phone is short of room, at the five sizes in both faces.

## Considered

- **A set never moves minutes** (the step's first idea). Fails a clock that ran on after a whistle (the audit's case c): that time was not played.
- **Keeping the tracker's meaning (time taken off is given to nobody) and only making a mistake put right exact.** Then a quarter played with time run off the clock reads 7:30 for those who played all 8:00. The game clock was chosen because a coach checks minutes against the scoreboard.
- **Correcting the old rule in place, for every game.** It would change the Al-Hadi tracker's numbers and every game already recorded.
- **A season setting.** There is one right answer; a setting would only let a league choose the wrong one.

## Not perfect

- A mistake that ran before it was put right is exact, to the millisecond, since the later set takes the earlier one back (worked by hand by the area 6 lead: two whole games, 108 moments, every minute and play time). What stays approximate, in the area 6 lead's words: two REAL corrections in opposite directions in one period with the clock running between are read as the second taking back the first (totals exact; a player swapped between them can be off by up to the smaller of the two); time the clock runs above the period's start counts for nobody; a period whose start was mistyped and noticed after the clock ran stays capped; a mistake not put right before the next period cannot be reached.
- A scorekeeper who forgot to start the clock at a period's start and takes time off before ever starting it gives nobody that time (the set only says where the period starts); the other choice would add minutes nobody played whenever a period is shortened on purpose.
- A set above the period's start reads, until it is corrected, as "nothing played yet this period" for every earlier moment of the period; once a later set takes it back, every earlier moment reads as before.

## Revisit if

- A league plays without a game clock, or with one the scorekeeper does not keep: minutes then need another source.
- The Al-Hadi tracker is retired: the old rule and its pin can go with it.
